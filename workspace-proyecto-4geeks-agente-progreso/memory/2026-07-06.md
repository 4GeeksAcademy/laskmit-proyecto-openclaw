# 2026-07-06 — Memory Log

## Problema: Archivos multimedia corruptos (contenido HTML, metadata image/jpeg)

### Problema detectado
- Los documentos (Quilling, Limpieza/Detox, Recetas, Resina) se crearon correctamente en Google Docs con tablas y links clickables
- Pero los adjuntos multimedia aparecen con icono de Google Docs en lugar de imágenes/videos
- Causa raíz: `GOOGLEDRIVE_UPLOAD_FROM_URL` descarga la **página de advertencia HTML** de Google Drive en lugar de la imagen real. La metadata se queda como `image/jpeg` pero el contenido binario es `text/html`
- `GOOGLEDRIVE_COPY_FILE` preserva fielmente ese contenido corrupto (md5 checksum idéntico entre original y copia)

### Intentos fallidos de solución
1. **UPLOAD_FROM_URL** → descarga HTML
2. **COPY_FILE** → preserva contenido corrupto
3. **Descargar desde VPS con wget** → Google Drive bloquea descargas anónimas (redirige a login)
4. **API autenticada desde sandbox Composio** → sandbox no puede hacer HTTP saliente a Google API
5. **Servir desde VPS** → archivo en Drive no accesible sin auth

### Solución final
- ✅ Limpié `multimedia/` (ID: `1Np-hgEXF7PenohoEsJ4WhPBckBAWa5s1`) — borrados todos los archivos corruptos
- ✅ Solicité a Yolanda que suba las 15 imágenes directamente desde su teléfono/PC a la carpeta multimedia (arrastrando desde galería, NO usando "Copy to" de Drive)
- ⏳ Pendiente: Yolanda debe confirmar que subió las imágenes, luego reconstruir docs con links correctos

### Archivos necesarios (para referencia futura)
| Categoría | Archivos |
|-----------|----------|
| Quilling | IMG-20250821-WA0002 al WA0007, WA0000/WA0001 del 20251222, WA0000 del 20251224, WA0000 del 20260104, WA0001 del 20260217 |
| Limpieza/Detox | IMG-20260101-WA0000, IMG-20260201-WA0000 |
| Recetas | IMG-20220112-WA0001 |
| Resina | IMG-20230318-WA0003 |

### Lecciones aprendidas
- **NUNCA usar `GOOGLEDRIVE_UPLOAD_FROM_URL` con URLs de Google Drive** — siempre descarga página HTML de advertencia/login
- `GOOGLEDRIVE_COPY_FILE` para mover entre carpetas de Drive funciona bien (preserva mime y contenido) pero no acepta `name`/`parents` aunque la API los soporte
- No existe tool `GOOGLEDRIVE_RENAME_FILE` en las tools composio disponibles
- Para archivos multimedia en Drive, la única forma segura es que el usuario los suba manualmente o usando la API autenticada directamente
- `GOOGLEDRIVE_MOVE_FILE` funciona con `file_id` y `add_parents` (string)

### Estado actual
- Docs creados correctamente con contenido y links (excepto multimedia corrupto)
- multimedia/ está vacío/listo para recibir archivos reales
- SKILL.md actualizado con procedimientos
- Archivos .md de categorías generados en `Desde_chat_original/`
